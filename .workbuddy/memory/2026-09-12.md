# 2026-09-12 工作日志

## MPC-HC 频闪/黑帧问题定位（Road 1 D3D11→D3D12 桥接）

**现象**：MPC-HC + MPC-VR 上用 sm86_smooth（Smooth Motion / NvPresent64）出现频闪，疑似两帧之间夹黑帧，
屏幕录制抓不到。

**结论**：黑帧发生在 DWM 合成层之下（DXGI flip / scanout 阶段），不在渲染内容里。
"录屏录不到"这一条本身就锁定了层级——录屏抓的是合成结果。

**实测数据（本机 RTX 3080 / 驱动 616.56 / 3840x2160 @ 143.99Hz + 200% 缩放）**：
- 显示输出实测：DWM 合成 refresh period **6.945ms = 143.99Hz**（`capture_out/refresh_probe.exe`）。
- 片源 24fps → 插帧 48fps → **144Hz 正好 3:1，节拍干净** → "节拍失配/pulldown"类解释已排除。
- 桥接每帧阻塞仅 ~0.5ms（D3D11 拷贝+查询 197µs、D3D12 拷贝+fence 325µs）→ 不是节拍瓶颈。
- 5 种 sync/flags 组合（含 MPC-VR 的 sync=0+ALLOW_TEARING 撕裂模式）全部 present 成功，每次 1 次 cuGraphLaunch。
- 影子交换链缓冲索引每次 Present 只 +1（非 +2）→ **驱动的生成帧走独立上屏通路，应用侧不可见**，
  这就是为什么任何合成/交换链级抓取都抓不到它。
- `IDXGISwapChain::GetFrameStatistics()` 在 NvPresent 包装交换链上**恒返回 0**，不可用于节拍诊断。
- D3D11 flip 交换链的 `GetCurrentBackBufferIndex()` **恒为 0**，`GetBuffer(1..3)` 返回 0x887A0001；
  D3D11 由运行时代管翻页，`GetBuffer(0)` 即当前后备缓冲 → 把它"修"成 GetCurrentBackBufferIndex 是空操作。
- ⚠️ 教训：探针里的 `Sleep` 用户态 pacer 实测出的 dt **不能当 vsync 间隔**用（我曾据 16.7ms 误判 60Hz 面板）。

**代码层确认的缺陷**：
1. 子窗口影子交换链创建即 `WS_VISIBLE` 且无内容（无背景刷、WndProc 不绘制）→ 首次 Present 前是黑矩形。
2. 分辨率/尺寸变化即整体 `Shutdown()`+重建（日志里反复重建）→ 每次重建都闪黑，并让生成帧丢失历史。
3. `HookedPresent` 吞掉 Present 返回值恒返回 S_OK → 应用收不到 `DXGI_STATUS_OCCLUDED`，节拍反馈断链。
4. `ALLOW_TEARING` flag 直传给未带该 flag 的影子交换链（DXGI 契约违规；NVIDIA 帧生成本应走同步路径）。

**当前最高优先怀疑（144Hz 已定案后的排序）**：
1. MPC-VR 撕裂/无垂直同步（sync=0 + ALLOW_TEARING）与驱动插帧的组合。
2. VRR/G-Sync：面板级亮度闪烁天生不被录屏捕获，与"录不出来"高度吻合。
3. 第二条 scanout plane（子窗口影子交换链）+ 应用自身 D3D11 交换链也被激活了 Smooth Motion，
   4K144(DSC) 带宽紧 → plane 重配频繁 → 只体现在面板上的黑闪。

**复现/验证手段**：SM86_DIAG=1 打开桥接 per-present CSV（dt/buf_idx/阻塞耗时/hr）；
`tools/bmp_stats.py`（BMP 黑帧判定）；`tools/analyze_frames.py`（录屏逐 tile 时间中值异常检测，
可抓整帧黑与局部黑条）。scanout 级现象最终需光学拍摄（手机慢动作）取证。

**产出**：`FLICKER_ANALYSIS.md`（含完整证据链与按性价比排序的验证步骤 + 附录 A 对另一 agent 修复报告的核验）。

## 01:18 手机慢动作取证：确认是扫描层撕裂 + 缓冲交接问题（已定方向）

**机械含义**：flip 落在扫描行程上的**相位随机** = 真撕裂；两侧至少有一侧**不是有效帧**

→ **不是插值画质问题，而是桥接与驱动对"哪张缓冲空闲"没有共识**。

## 01:43 PresentMon 实测：根因确定为"驱动侧撕裂模式呈现"（应用侧无法修改）

用户回答：**"几乎每个帧都撕"**；**"拖着播放器窗口动时不闪，但好像也没补帧"**。

**方法**：PresentMon 2.5.1（自下载）`--process_name mpc-hc64.exe --timed 20 --v1_metrics`，
配自生成 testsrc2 片源（24/36/48fps）；
`capture_out/display_timeline.py` 从 `TimeInSeconds + msUntilDisplayed` 重建真实上屏时刻，
统计"上屏间隔 < 1 vblank(6.944ms)"次数 = 扫描中途换缓冲（撕裂）。

**结果**：
| 源帧率 | 上屏更新率 | 撕裂比例 | 从未上屏 |
|---|---|---|---|
| 24fps | 48.4/s（2×24 ✓） | 143/724 = **19.8%** | 4 |
| 36fps | 57.5/s | 126/867 = 14.5% | 215 |
| 48fps | 96.1/s（2×48 ✓） | 295/1246 = **23.7%** | 4 |

**全部 present**：`SyncInterval=0` + `PresentFlags=0x200(ALLOW_TEARING)`，
而同一时刻桥接日志显示我们提交的是 `sync=1 flags=0x0`。
PresentMon 捕获的交换链地址 `0x6963910` ≠ 我们的影子交换链 `m_swap12=0x794290C0`
→ **真正上屏的是驱动内部那条交换链，我们的 Present 参数到不了那一层**。

**结论**：驱动/代理把请求覆盖成 `sync=0 + 撕裂`；sync=0 下翻转立刻生效 → 扫描中途换缓冲 →
水平随机撕裂线，合成帧只以"半屏"出现（与"没见过完整的一帧"吻合）。
撕裂与源帧率无关（14–24%）→ 对齐帧率不是解法。
**"拖窗口时不闪"印证机制**：拖动时无法 Independent Flip → 走 DWM 合成 → 按 vblank 调度 → 不撕。

**可行路径**：A. 开 G-Sync/VRR（VRR 下翻转即一帧扫描起点，可能直接消除撕裂，零改动先试）；
B. 强制走 DWM 合成（验证此时 `cuGraphLaunch` 是否仍在）；
C. 换插值实现（MPC-VR `InterpolateAt50pct`，或本项目 Road 2 HLSL VFI，基于整帧天然免疫）。
D. 继续调桥接参数 → **已证伪**。

**新增工具**：`capture_out/display_timeline.py`、`capture_out/analyze_presentmon.py`、

## 02:10 ReShade add-on 路线打通（方案 C 落地）

**安装**：ReShade **6.8.0（API 20）**装成 MPC-HC 目录的 `dxgi.dll`；`sm86_smooth.addon64` 同目录。
API 版本必须精确匹配才能被加载（6.5.0=17 / 6.6–6.7.3=18 / **6.8.0=20**）。详见 `RESHADE_ADDON_INSTALL.md`。

**决定性测量（PresentMon + 上屏时刻重建，vblank=6.944ms）**：
- 桥接（驱动 FG）：48.4/s，撕裂 **19.8%**
- **ReShade 注入（无桥接）：24.4/s，撕裂 0.0%（0/222）**
- ReShade + `InterpolateAt50pct=1`：24.4/s，0.0%（该选项**不提高** present 频率）
- ReShade + 桥接同时：**启动即崩**（`ResizeBuffers(2617x1689)` 处 ACCESS VIOLATION）

**→ 撕裂是"驱动 FG + independent flip"的组合行为；ReShade 把 present 拉回 DWM 合成后撕裂彻底消失。**
**两条路线互斥，当前部署 ReShade-only，桥接件停放在 `VERSION.dll.off_for_reshade`。**

**add-on 崩溃根因（已修）**：`on_bind_render_targets_and_depth_stencil` 收到 `count=8` 但
`rtvs[0].handle==0`（D3D11 的空 RTV slot），直接交给 `get_resource_from_view()` → ReShade 内部解引用 0x0。
修复：跳过空 slot、逐级判空、按真实 RT 尺寸重建快照（init 时 D3D11 给的是 **8x8 占位 backbuffer**）。
修复后连续播放 20s 无崩溃。

**仍未达成**：ReShade 路径下**无插帧**，且有两道坎：
1. 跨 API —— ReShade 层是 D3D11，`sm86::VfiEngine` 是 **D3D12 专用**；
2. 帧率倍增 —— MPC-VR 只按源帧率 present，需在 `on_present` 里自己多产生一次上屏。
